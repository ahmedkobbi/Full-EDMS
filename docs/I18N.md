# Smart EDMS — Internationalization Specification

> Spec reference: §16 (Mandatory Internationalization Requirement).

## Required Locales

Smart EDMS supports six mandatory locales from day one:

| Code     | English Name        | Native Name  | Direction | BCP-47 (Intl) |
|----------|---------------------|--------------|-----------|----------------|
| `en`     | English             | English      | LTR       | `en-US`        |
| `fr`     | French              | Français     | LTR       | `fr-FR`        |
| `ar`     | Modern Standard Arabic | العربية   | RTL       | `ar`           |
| `ru`     | Russian             | Русский      | LTR       | `ru-RU`        |
| `zh-CN`  | Simplified Chinese  | 简体中文      | LTR       | `zh-Hans-CN`   |
| `de`     | German              | Deutsch      | LTR       | `de-DE`        |

Arabic is implemented as Modern Standard Arabic (MAS/MSA) unless the Product Owner defines another precise Arabic variant.

## Mandatory Use of `t()`

Every user-facing string must use `t()`. This includes:

- Page titles
- Buttons
- Labels
- Placeholders
- Tooltips
- Validation messages
- Error messages
- Empty states
- Loading states
- Table headers
- Menu items
- Modal titles and bodies
- Confirmation dialogs
- Notifications
- License states
- WebSocket event messages shown in UI
- Admin panel labels
- Guided tour content
- AI assistant UI chrome
- Marketing page copy (rendered through React components)
- Installer UI text (where supported)
- Email subjects and bodies (rendered through shared templates)

### Forbidden

- Hardcoded English text in components
- Hardcoded French text in components
- Hardcoded Arabic text in components
- Hardcoded Russian text in components
- Hardcoded Chinese text in components
- Hardcoded German text in components
- Concatenated translated fragments (broken plurals/cases)
- Untranslated validation messages
- Untranslated API error messages shown to users
- Untranslated tour content
- Untranslated AI assistant UI labels

### Correct pattern

```tsx
// ❌ Forbidden
<Button>Save Document</Button>

// ✅ Correct
<Button>{t('common.actions.save')}</Button>

// ❌ Forbidden (concatenation)
<Text>{t('documents.count')} {count}</Text>

// ✅ Correct (ICU interpolation)
<Text>{t('documents.countLabel', { count })}</Text>
// Key: "documents.countLabel": "{count, plural, one {# document} other {# documents}}"
```

### CI Validation

Translation files are validated in CI via `pnpm i18n:check`. The checker:

- Walks all locale files
- Reports missing keys vs the `en` baseline
- Exits non-zero if critical namespaces (errors, license, audit, security, retention, classification, ai.disclaimer, ai.errors, tour.license, tour.audit) have missing keys
- Reports unused keys (where practical)
- Validates interpolation variables
- Validates ICU plural syntax
- Validates RTL/LTR direction correctness

## Language Switcher with Flags

The language switcher displays:

- Native locale name (e.g., "العربية" not "Arabic")
- Flag icon or configured visual indicator
- Active state
- Accessible label

### Required visible locales

| Native Name | Code |
|-------------|------|
| English | `en` |
| Français | `fr` |
| العربية | `ar` |
| Русский | `ru` |
| 简体中文 | `zh-CN` |
| Deutsch | `de` |

### Flag rules

- Use a flag icon system or custom SVG components
- Flag mapping must be **configurable per tenant** (stored in `Tenant.flagConfig`)
- Do NOT hardcode political assumptions for language-to-flag mapping
- For Arabic MAS/MSA, use a **neutral indicator by default** (spec §4.5)
- If a flag is required for Arabic, make it configurable at tenant level
- Always include native locale names — do not rely on flags alone for accessibility

## RTL Requirements (Arabic)

For Arabic locale (`ar`):

- Set `dir="rtl"` on `<html>` element
- Set `lang="ar"` on `<html>` element
- Use Mantine RTL support via `<MantineProvider theme={{ dir: 'rtl' }}>`
- Use CSS logical properties: `margin-inline-start`, `padding-inline-end`, `inset-inline-start`, etc.
- Use logical spacing utilities: `ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`
- Mirror directional icons (arrows, chevrons, back/forward)
- Do NOT mirror non-directional icons (lock, search, settings, document)
- Ensure tables, drawers, modals, menus, pagination, breadcrumbs, date pickers, and forms work correctly in RTL
- Ensure Electron desktop layouts remain stable in RTL
- Ensure license screens, admin screens, guided tours, AI assistant bubble, and marketing pages support RTL

### RTL testing checklist

- [ ] Login screen renders RTL
- [ ] Sidebar appears on the right side
- [ ] Topbar navigation flows right-to-left
- [ ] Tables: first column on the right, pagination reversed
- [ ] Drawers open from the left (logical "end" in RTL)
- [ ] Modals: close button on the left
- [ ] Date pickers: calendar grid is RTL
- [ ] Forms: labels on the right, inputs on the left
- [ ] Tooltips: positioned with logical start/end
- [ ] Notifications: slide in from the right
- [ ] Tour overlays: popover positioning uses logical placement
- [ ] AI assistant bubble: positioned at bottom-start (logical "end" in RTL)
- [ ] Marketing page: hero text flows RTL, navigation reversed

## Date, Number, and Plural Localization

### Required behaviors

- Use `Intl` APIs (or equivalent locale-aware formatting) for all dates, times, numbers
- Support locale-specific number systems (Arabic-Indic digits, Chinese numerals where appropriate)
- Support locale-specific date formatting (DD/MM/YYYY vs MM/DD/YYYY vs YYYY-MM-DD)
- Support timezone-aware display (user's preferred timezone)
- Support Arabic plural rules (6 forms: zero, one, two, few, many, other)
- Support Russian plural rules (3 forms: one, few, many)
- Support German plural rules (2 forms: one, other)
- Support French plural rules (2 forms: one, other)
- Support Simplified Chinese formatting (no plural distinction)
- Support locale-aware week start (Monday in EU, Sunday in US)
- Support translated month and weekday names

### ICU MessageFormat examples

```
// English (one/other)
"documents.count": "{count, plural, one {# document} other {# documents}}"

// Arabic (zero/one/two/few/many/other)
"documents.count": "{count, plural, zero {لا مستندات} one {مستند واحد} two {مستندان} few {# مستندات} many {# مستندًا} other {# مستند}}"

// Russian (one/few/many/other)
"documents.count": "{count, plural, one {# документ} few {# документа} many {# документов} other {# документа}}"

// Simplified Chinese (no plural distinction)
"documents.count": "{count} 个文档"
```

### Date formatting examples

```typescript
import { formatDate } from '@smart-edms/i18n';

formatDate(new Date(), 'en'); // "Aug 15, 2026"
formatDate(new Date(), 'fr'); // "15 août 2026"
formatDate(new Date(), 'ar'); // "١٥ أغسطس ٢٠٢٦"
formatDate(new Date(), 'ru'); // "15 авг. 2026 г."
formatDate(new Date(), 'zh-CN'); // "2026年8月15日"
formatDate(new Date(), 'de'); // "15. Aug. 2026"
```

## Machine Translation Policy

Machine-only translations are NOT allowed for (spec §10.6):

- Compliance explanations
- License warnings
- Audit instructions
- Security guidance
- Legal hold explanations
- Retention explanations
- AI safety explanations

For these critical namespaces, files contain a `// REVIEW: native speaker needed` header comment indicating that a human reviewer must verify the translations before production use.

For non-critical namespaces (common UI labels, navigation, etc.), machine translation with human review is acceptable.

## Locale Resource Override

Tenants may override specific translation keys via the `LocaleResource` table. This allows:

- Tenant-specific terminology (e.g., "Records" vs "Documents" for a legal tenant)
- Tenant-specific legal text
- Tenant-specific branding copy

Overrides are loaded at runtime and merged with the bundled resources. The merge priority is: tenant override > bundled resource.
